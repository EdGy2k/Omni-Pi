## Dependency notes

- **000 first:** Pi 0.84.1 adds GPT-5.6 Luna/Terra/Sol and the `max`
  reasoning level. pi-subagents 0.45.1 replaces the public parallel/chain
  surface with `workflowScript` and adds stronger workflow, gate, mission, and
  worktree primitives. Designing against 0.37.2 would immediately create a
  second migration.
- **001 before 002/004:** task identity and lifecycle must exist before content
  evidence or artifact paths can be bound to a work item.
- **002 before broad worker use:** isolated workers remain non-authorizing until
  the coordinator can verify and stage their applied content.
- **003 may run after 001 in parallel with 002 only in an isolated worktree.**
  In the normal checkout, keep one writer and execute sequentially.

## Direction options after these plans

- Add a visual workflow inspector from the authoritative runtime state only
  after the state schema is stable. The current repo already has plan-review
  and Fleet surfaces, so a separate status UI would otherwise duplicate state.
- Consider moving GedCode onto the same **vocabulary and artifact contract**, not
  the same Pi extension enforcement. GedCode should not claim guarantees its
  server does not own.

## Findings considered and rejected

- **Remove `pi-intercom` entirely:** rejected. Native pi-subagents coordination
  should own child-to-supervisor decisions, but external intercom remains useful
  for user-directed independent sessions and genuine peer dependencies. Make
  peer use policy-controlled rather than deleting the user feature.
- **Treat every project instruction file as hostile data:** rejected as stated.
  `AGENTS.md` and explicitly imported `.ged/STANDARDS.md` are intentionally
  authoritative project guidance. Arbitrary repo-map text and model-written
  durable notes still need clear data delimiters and cannot override system,
  user, governance, or publication authority.
- **Keep repairing schema v3 role checkpoints:** rejected. The approved policy
  checkpoints safety evidence, not whether named roles ran.
- **Make human plan review mandatory:** rejected. Human approval remains a
  preference or high-impact gate; ordinary direct changes should not pay that
  ceremony.
- **Automatic one-off skill creation:** rejected. A task brief is not a reusable
  skill. Plan 004 removes this behavior rather than refining generated prose.

## Audit limits

- The targeted audit deeply reviewed workflow, checkpoint, agent-settings,
  intercom, memory, and related test surfaces. UI themes, repo-map ranking,
  updater behavior, and vendored diff-review internals were not audited.
- Four read-only audit children returned useful findings but their runs were
  marked failed because the current pi-subagents acceptance inference required
  `changed-files` evidence from read-only agents. That failure itself supports
  replacing prompt/name inference with explicit read-only contracts. Their
  claims were independently checked before inclusion here.
